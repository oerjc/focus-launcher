# 专注桌面 (Focus Launcher)

Android 专注启动器。把它设为默认桌面后，主屏幕只显示**本次会话允许**的应用。修改名单需要强生物识别或设备锁屏凭据。换回系统桌面、电话和系统设置不需要验证。重启后会话作废，必须重新选择。

包名 `com.focuslauncher.app`，版本 `1.0.1`，最低 Android 9（API 28）。

**Focus Launcher** is a home-screen replacement. The grid shows only the apps chosen for the current session. Reboot clears that session. Phone, Settings, and 「恢复系统桌面」 stay available without biometrics. It does not lock the device. Changing the allow-list still asks for a strong biometric or the device credential.

## 安装

从 [v1.0.1 Release](https://github.com/oerjc/focus-launcher/releases/tag/v1.0.1) 下载 `FocusLauncher-debug.apk`。这是 debug 签名包，可直接安装；若系统拦截未知来源，允许该来源后再装。已安装 1.0.0 时直接覆盖安装即可，会话数据仍在本应用里。

安装后打开「专注桌面」，或在系统设置里把它选为默认主屏幕应用。

## 设为默认桌面

应用注册为 `HOME`。当前不是默认桌面时，主界面会显示提示和「设为默认桌面」，打开系统的「主屏幕应用」设置。该页打不开时，依次尝试「默认应用」、本应用详情和系统设置。

只有设成默认主屏幕之后，按 Home 才会回到专注桌面。

## 本次会话允许名单

没有有效会话时，进入「今天要打开哪些应用？」。列表来自本机带启动器入口的应用（不含专注桌面自己），可按名称或包名搜索。至少勾选一项并确认后，名单写入本次会话。

桌面以四列网格显示这些应用，每个包名只保留一个图标。会话中途要改名单，点「解锁后修改名单」，验证通过后重选；已选项会预先勾上。

选择页不再吃掉返回。已有会话时，返回交给系统（预测性返回 / 边缘滑动可以离开这一页）。还没有会话时，返回同样离开选择页，回到桌面；桌面不会立刻把选择页再次盖上来。空名单时用「选择今日应用」再进去即可。选择页底部始终有「恢复系统桌面」「电话」「设置」，都不需要验证，也不需要边缘滑动。

## 生物识别与设备凭据

只有「解锁后修改名单」使用系统 `BiometricPrompt`，接受：

- 强生物识别（`BIOMETRIC_STRONG`）
- 设备凭据（`DEVICE_CREDENTIAL`：锁屏 PIN、图案或密码）

设备上还没有可用的锁屏凭据或生物识别时，修改名单会失败，并提示先到系统设置里配置。取消验证不会改名单。

「恢复系统桌面」、电话和设置不经过这道验证。手势已经失效、或者这台手机还没设锁屏时，仍然点得开。

## 重启清空会话

会话保存在本应用的 `SharedPreferences` 里，并用两处逻辑在开机后失效：

1. `BootReceiver` 收到 `BOOT_COMPLETED` 后清空会话。
2. 建立会话时记下 `SystemClock.elapsedRealtime()`。重启后这个开机计时从零附近重新开始；若当前值小于保存值，会话视为已失效并清除。

因此每次开机都要重新选择今日应用。进程被系统杀掉但没有重启时，名单仍然有效。会话不按时钟时间自动过期。

## 电话与设置

主界面和选择页的「应急」出口不占用允许名单，也不需要解锁：

- **电话**：打开系统拨号界面（`ACTION_DIAL`），只进入拨号盘，不会直接呼出。
- **设置**：打开系统设置。
- **恢复系统桌面**：直接打开系统的「主屏幕应用」设置（`ACTION_HOME_SETTINGS`），用来点选原来的系统桌面。该页打不开时，依次尝试「默认应用」、本应用的「应用详情」，最后才打开系统设置，并提示去哪里改桌面。它不会卸载本应用，也不弹出生物识别。

在默认桌面被改掉之前，按 Home 仍会回到这里。主屏幕本身没有上一页，边缘滑动不会把桌面划掉；第一次这样滑动时会提示去点「恢复系统桌面」。

## 全面屏手势

从屏幕边缘向内滑动是系统导航，不是本应用的手势。本应用不会：

- 调用全屏 / 沉浸式 / 粘性隐藏导航栏
- 设置 `systemGestureExclusionRects` 去挡住边缘
- 在已有会话时用返回回调吃掉预测性返回

界面按系统栏、刘海和系统手势区域做了内边距，避免不透明按钮贴死在屏幕边缘。

这修不了所有机型。小米、OPPO、vivo、华为等厂家常常把全面屏返回做在**系统桌面进程**里。本应用一旦成为默认主屏幕，那段手势服务可能直接停掉，第三方桌面无法在仍担任默认 HOME 的同时把它重新接上。

若边缘滑动仍然无效：

1. 点「恢复系统桌面」，在系统列表里改回系统自带桌面（系统桌面 / 小米桌面 / 华为桌面等）。改回之后，系统手势一般会恢复。
2. 或先到系统设置里把导航方式暂时改成**三键导航**（返回、主屏、最近任务三个按键），不依赖边缘滑动。

正在用 1.0.0、选择页把返回吃掉、又划不出去时：先至少勾选一个应用并确认，回到桌面后点底部「设置」（不用验证），再把默认桌面改回去。1.0.1 起选择页上就有「恢复系统桌面」。

## 能力边界

专注桌面替换的是主屏幕入口，不是设备主人模式、工作资料或屏幕固定。

- 通知、最近任务、快捷设置、分享、深链，以及已经在运行的应用，仍可能打开不在名单中的应用。
- 没有小部件、文件夹、壁纸、手势导航定制，也没有包含全部应用的抽屉。搜索只在选择名单时可用。
- 只列出声明了 `MAIN` / `LAUNCHER` 的活动，并依赖 `QUERY_ALL_PACKAGES` 枚举已安装应用。同一包名的多个启动入口合并成一个图标。
- 随 Release 提供的 APK 是 debug 构建（`versionName` 1.0.1，未混淆），不是应用商店用的 release 签名包。
- 不能在继续担任默认主屏幕的同时，保证所有 OEM 的全面屏返回都恢复。能做的是不拦截系统返回，并提供不依赖该手势的换桌面入口。

## 从源码编译

需要 JDK 17 和 Android SDK（`compileSdk` 34）。

```bash
./gradlew assembleDebug
```

产物路径：`app/build/outputs/apk/debug/app-debug.apk`。
